# 结果怎么读，错误怎么处理

## 训练目录里的文件

| 文件 | 实际含义 |
|---|---|
| `input-report.json` | 原始文件内容 SHA、投影/忽略列、dtype转换、连接匹配/缺失/多余键；先审阅它再解释模型 |
| `run.json` | 任务、显式类别、参数、后端、最佳模型、SplitPlan摘要；结局来源声明 |
| `best-model.rad` | 通过训练 CV 比较选择的可移植模型；不包含可执行 Python pickle |
| `training/model-*.rad` | 每个模型的类型化拟合状态；文件编号与 `training/training.json`、CV结果联合查看 |
| `training/split_plan.json` | 实际患者队列/内外层折和种子；审计是否患者泄漏 |
| `training/cv_results.csv` | 外层每模型/每折比较分数，不等同独立外部验证 |
| `training/oof_predictions.csv` | 每个训练患者被排除于该次拟合后形成的 OOF 预测，保留 fold 与 training_source |
| `training/predictions.csv` | 最终模型的 train/test/external 预测；看 prediction_type/cohort，不只看分数 |
| `oof-metrics.csv` | 单独对 OOF 预测评价；cohort 仍为真实 `train`，OOF 身份由 prediction_type/training_source保留 |
| `cohort-metrics.csv` | 按原队列分别评价；纯无标签队列为 prediction_only，不产生伪指标 |
| `holdout-*-*.png`、`plot-cohorts.json` | 有标签的 test/external 患者图，数字文件名与真实队列映射；train 不画成留出图 |
| `external-predictions*.csv/json` | 仅在传入 `--predict-study` 时生成；保存加载后一致性已经检查 |

脚本的指标 `CI=None`，因此没有偷偷用几十次 bootstrap 声称稳定置信区间。研究需要 CI 时在设计中预先固定方法/复制数，用 `rad.evaluate(..., prediction_unit="patient", ci_method="bootstrap", n_bootstrap=2000, random_state=...)`。二分类 DeLong 保持二分类语义；小样本中 AUC、校准和 CI 都可能不稳定。

## 从三个角度解读图

二分类 ROC 描述不同阈值下排序区分能力，不决定临床阈值；校准图描述预测概率与实际比例是否相符，少量患者的每个分箱很不稳定；混淆矩阵依赖保存的预设阈值和明确的阳性类别。高 AUC 不自动意味着概率可靠或临床有效。

多分类图是各类别 OvR 曲线，报告同时区分 macro/micro/weighted 汇总。类不平衡时应查每类表现，不能只读一个总准确率。回归散点偏离对角线表示误差；应结合真实目标单位、MAE/RMSE/R²和残差分布解释，不能把 R² 当作分类准确率。

`train` 表观结果通常更好；模型比较、候选选择或融合训练使用过的 OOF 结果仍有选择不确定性。最终结论需要固定且身份清楚的测试/外部队列。模型用于临床前的适用性、偏倚和部署评估不由软件单例演示完成。

## 常见错误与修复位置

| 现象/报错含义 | 应检查什么 |
|---|---|
| 样本 ID 重复 | 一行是否真的对应唯一ROI/tile；为多病灶建立不同sample_id，同时保留相同patient_id |
| clinical duplicate key / exact key sets differ | patient-key临床表必须每患者唯一；移除当前研究之外的患者应在输入准备时显式完成，不按行数截断 |
| conflicting metadata | features、metadata、clinical中的已知ID/cohort/center矛盾；修改源表，不依赖自动后缀或覆盖 |
| patient occurs in multiple cohorts / overlap | 同一患者被拆到train/test/external；统一真实患者键并重做预先划分 |
| fold missing class / insufficient grouped patients | 每类训练患者不足，或患者组约束无法满足折数；重审研究设计，显式调整cv，不能改成随机行划分 |
| unknown category | 外部类别训练未见；核查拼写/编码与预定义临床字典，不能在外部重新fit one-hot |
| all-missing column / zero features | 列是否选错、真实变量是否全缺；不要自动填0或降低筛选阈值直到通过 |
| incompatible numeric / infinity / complex | 声明类别角色；明确缺失token；去除数据导出中的Inf/非法编码；不能丢弃复数虚部 |
| missing feature / feature type mismatch | 外部必须提供训练所需名字与类型；只允许按名称重排，不能以同列数替代定义一致性 |
| nonconvergence / rank deficient / separation | 优化/统计模型有效性失败；核查共线性、样本量和完全分离，不将失败模型保存为成功 |
| native extension predates API | 当前Python代码与安装的旧扩展不匹配；安装匹配的完整构建，不回退外部Python算法假装原生 |
| FileExistsError | 选新输出目录；本教程不覆盖已有模型/结果 |
| checksum / sidecar mismatch | 特征表曾被编辑或配错manifest；重新从明确来源导出，保留旧版本，不篡改SHA使其通过 |
| patient plot outcomes disagree | 同患者有不同样本结局；确认目标层级，必要时采用显式sample评价并省略患者图 |
| no labeled outcomes / prediction_only | 新队列没有真实结局是正常预测状态；不能据预测值生成AUC或回归评价 |

## 病理特有的边界

所有 patch 被 QC 排除的切片返回空结果状态，不能用一行全零代替它。记录哪些父级因无有效特征不能进入模型；若要排除，需要在研究表中明确记录原因，并使 features/clinical exact键集合对应。

重叠 patch 的实例数不能直接加成全切片细胞总数；没有全局实例 ID 时仅解释 patch-local 统计。图中的实际 tile 特征或真正 tile 模型分数可以覆盖到坐标上；**患者概率不能广播成局部病理概率图**。没有已知 MPP 时只读像素尺度，不从20x/DPI猜μm。

## 换成自己数据时的检查顺序

1. 写下研究对象、预测时间点、真实结局定义和单位、患者键、预定训练/测试/外部队列。
2. 先检查一两例图像/patch与mask/坐标，再冻结提取参数和特征定义。
3. 在JSON中明确特征/类别/结局/ID角色；先查看input-report和连接质量。
4. 跑保守少量特征/单模型，检查SplitPlan、OOF、cohort身份和保存加载。
5. 将筛选/参数网格加入完整患者分组pipeline；以新输出目录保留新分析方案和结果。
6. 单独报告固定测试和每个外部队列，记录缺失/QC排除、限制和所有性能目标未达项。

可执行软件通过不意味着医学研究设计自动成立。上述顺序是让每一步可审查，而不是提供临床标签或替你决定研究终点。
