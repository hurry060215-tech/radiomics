# Reproducible native package assets and source builds

The canonical reference files remain under repository `golden/`. No maintained
fixture copy was moved or duplicated. `tools/package_native.py` creates ignored
crate-local `package-assets/` directories only for packaging, verifies source and
staged bytes, and emits an inventory. It never publishes, changes versions,
edits dependency requirements or updates the repository Cargo.lock/Golden.

## Asset preparation and source compilation

The Python sdist also carries the six native tutorials, their shared helper,
the two redistributable Golden profiles, Python validation/build tools and
benchmark plans. The noncommercial public CT profile and its dependent tests
remain repository/external-validation assets and are explicitly excluded from
the installation source archive. This separation preserves their independent
license without shipping unusable CT-specific tests in the sdist. Archive
membership is checked before standalone tutorial/test validation; membership
alone is not a claim that every packaged command was executed.

The `source-delivery-v1` archive was actually unpacked and all six native tutorial
scripts were run from that unpacked tree with the installed immutable-v3 wheel
in the native-only environment. All six exited successfully, using the archive's
own helper/fixtures and producing models, tables and overlay figures. Evidence is
`E:/radiomics-build/source-delivery-v1/tutorial-evidence.json`, which records the
archive hash and individual output provenance. This checks packaged tutorial
execution; the separate derived-lock source-build evidence remains distinct.

For an immutable, native-host wheel/CLI snapshot from a clean source commit:

```powershell
python tools/build_native_snapshot.py --output artifacts/new-native-snapshot
```

This uses the existing compiler/maturin without installing or publishing. It
fixes release optimization to level 3, thin LTO and one codegen unit; records
source commit/tree, compiler/target/flags, lock hash, wheel/CLI/file hashes and
the compiled `_native.IMPLEMENTATION_SHA256`; and rejects source changes during
the build. Its receipt identifies a build, not correctness or speed acceptance.
Performance workers verify the receipt and installed bytes before measuring.

```powershell
python tools/package_native.py --output artifacts/package-preparation
```

The tool reads only the `files_sha256` allowlists in the frozen
`python_golden_v1` and `ibsi_digital_v1` manifests. It checks every input before
writing any staged output. Unknown profiles, such as private/noncommercial CT
datasets, are never recursively copied. Core and CLI each receive the allowed
fixtures, original manifests, MIT source LICENSE, a package README, third-party
notices and a generated stage inventory. The binding crate receives documentation
and source-license material without another Golden copy.

IBSI image/mask bytes remain unchanged. Its CC-BY-4.0 license, Alex Zwanenburg
attribution and SOURCE_README stay alongside the digital phantom. The README and
notices distinguish MIT software from separately licensed fixtures. No blanket
MIT claim is made over third-party data.

Reuse is permitted only when existing generated bytes match exactly. Different
known generated files require explicit `--overwrite`; unexpected files or
symlinks in an asset tree are errors. The tool does not recursively delete an
unknown directory. Source archive derivation always uses a fresh output directory
to preserve its original archive, including when `--overwrite` is supplied.

The three Cargo manifests explicitly include `/package-assets`, despite that
directory being gitignored. This follows Cargo's documented include behavior and
was independently checked with actual `cargo package --list`, including hidden
IBSI source metadata, license and NIfTI files. Cargo distinguishes file-list
inspection from actual package build verification.
([Cargo manifest include rules](https://doc.rust-lang.org/cargo/reference/manifest.html#the-exclude-and-include-fields),
[Cargo package stages](https://doc.rust-lang.org/cargo/commands/cargo-package.html))

Core and CLI build scripts resolve `RAD_GOLDEN_DIR` at compile time. A real
ancestor Cargo.toml declaring `[workspace]` plus a `golden/` directory selects
the canonical workspace data. Otherwise the crate-local generated directory is
used. There is no external environment override, runtime skip switch or global
option. A missing data directory still emits its expected path, so ordinary
library compilation does not depend on fixtures; enabled tests fail naturally
if their data is absent. An actual isolated no-fixture `cargo check --lib
--locked` passed. Packaging through the tool requires verified assets first.

Only test include/read paths were changed. Expected values, numerical tolerances,
test logic and numerical algorithms were preserved. The original implementation
digest algorithm remains unchanged, including build.rs as one input; adding a
path-discovery build-script change naturally produces a new source identity.

## Core archive and development-only dependent archives

```powershell
python tools/package_native.py --crate core --package --test --allow-dirty `
    --toolchain 1.85.0 --target-dir artifacts/native-build-cache `
    --output artifacts/native-core
```

This runs file-list inspection, actual Cargo package verification, byte checks
against the staged manifest, and all targets from Cargo's unpacked archive. It
copies the resulting `.crate` to the report output. `--allow-dirty` is explicit
for a development checkout and remains visible in Cargo's VCS metadata; it does
not authorize publication or establish a clean release artifact.

CLI and bindings depend on the unpublished core version. Ordinary registry
packaging still fails when that version is unavailable. To verify development
archives using an already unpacked core artifact:

```powershell
python tools/package_native.py --crate cli --crate python --package --test `
    --allow-dirty --toolchain 1.85.0 `
    --target-dir artifacts/native-build-cache `
    --local-core artifacts/native-build-cache/package/ov-radiomics-core-0.1.0 `
    --output artifacts/native-dependent-crates
```

`--local-core` is explicit and recorded. Package preparation uses a registry patch
to the already selected workspace core, preserving the workspace lock. Standalone
archive tests instead patch to the provided unpacked core artifact. Using a
different unused patch in the original workspace would require a lock change;
the tool does not relax `--locked` or modify the source lock to hide that error.
The receipt records both paths and every command. These are local development
checks, not evidence of registry publication or independent crates.io install.
The binding crate's existing `publish=false` remains intact.

Keep Cargo's package extraction directory outside the original workspace when
running standalone archive tests. An unpacked crate beneath the repository's
`.build-tools/` can be mistaken for a member of the parent workspace even though
its archive is valid. The final core archive was verified after extraction to
`D:/radiomics-final-build/core-source-v1/`, where all 150 tests passed under
Rust 1.85 with `--all-targets --locked`. The earlier parent-workspace error is
retained in `final-core-crate-v2` logs; no source/expected value was changed.

The updated derived Python source archive also passed its locked all-targets
build and produced a wheel under Rust 1.85. That wheel was installed in a
separate source-test environment, and all 206 enabled Python tests were actually
run from the unpacked archive with `--import-mode=importlib -o pythonpath=`.
Its artifact-only lock removes unused CLI nodes while preserving all retained
dependency identities; the repository lock remains unchanged. Evidence is under
`.build-tools/final-native-source-v1/`. These are separate from the 71 tests of
the final native-only Windows wheel, which intentionally omits reference packages.

## Python source distribution with a derived artifact-only lock

Maturin includes the staged Cargo assets in its source archive. Its rewritten
workspace contains only core and bindings, removing the unrelated CLI member,
while its original Cargo.lock still contains CLI-only nodes. That original sdist
fails a locked Cargo check because its lock must be pruned. This behavior is
retained as evidence rather than silently called a successful locked build.

```powershell
python tools/package_native.py --crate core --sdist --toolchain 1.85.0 `
    --output artifacts/native-source-build
```

The source workflow preserves the original maturin archive, extracts into a fresh
artifact directory, and runs `cargo metadata --offline` against the existing
artifact-local lock. Every retained package's name/version/source/checksum must
exactly match the original lock; any added node, upgrade, downgrade or checksum
change aborts the operation. Only unused CLI-related nodes are removed. The
repository lock is checked unchanged. A deterministic gzip/PAX repackage preserves
all original members and bytes except that derived lock, with zero gzip header
mtime. The receipt records original/derived archive and lock hashes, removed
nodes, all raw commands and logs.

It then actually runs `cargo check --workspace --all-targets --locked` in the
derived source tree and a release `maturin build --locked` using the selected
Rust toolchain. These source checks do not use the development-only registry
patch. The original sdist remains available for exact review; no frozen fixture
or algorithm byte is changed by this derivation.
