生态分工：影像工具、组学接口与独立核心#

English · 安装

独立包负责明确范围内的特征提取和建模。OmicVerse 的可选适配层提供命名空间入口， 保留独立安装、计算核心和许可证边界。用户可以直接使用独立包或 CLI。

本轮的 ov.radiomics 是上游 PR #1096 中的候选适配器，仍待上游维护者合并和发行。公共 registry extra 目前保持注释占位； 评估该接口时，应先安装已验收的本地 wheel，并使用包含该 PR 的可导入 OmicVerse 工作树。它尚不构成已发行 OmicVerse 的一条命令安装承诺。

主要职责

维护与依赖边界

ov.radiology

DICOM 几何、测量、阅片

由 OmicVerse 维护的影像工具

ov.radiomics

适配代码位于 OmicVerse 仓库

ov_radiomics

明确的原生特征子集、具名表格、建模和评价

独立发行的 MIT 包

radiomics CLI

文件驱动提取、训练和预测

调用共享 Rust 核心，不需要 Python

    B[ov.radiomics：可选延迟适配] -->|独立安装边界| C
    C --> D[共享 Rust 核心]
    E[独立 radiomics CLI] --> D

图中是职责与调用关系，不为组学接口新增 DICOM 转换器，也不把 CT 体素包装成 AnnData 表达矩阵。外部已处理数组、mask 和 embedding 只按已有输入契约进入， 保留真实 ID、几何和处理来源。

适配层只在访问属性时加载独立包；import omicverse 不应新增影像后端或原生扩展 的即时导入。只有兼容 wheel 和相应 OmicVerse extra 实际发布后，才能把该入口写成 公开安装承诺。独立包不会反向依赖 OmicVerse。

独立包使用 MIT；OmicVerse 使用 GPL-3.0。GPL 项目可引用 MIT 包；不能把 GPL 实现 复制回独立包后按 MIT 发布。详情见贡献政策。

原生、可选 Python 和明确暂缓的范围见能力边界。 共享核心不意味着所有旧 Python 结果对象都支持原生绘图或序列化。
