Ecosystem and responsibilities#

简体中文 · Installation

The independent package owns feature extraction and modeling through its Rust core. An optional OmicVerse adapter provides a convenient namespace while retaining separate installation and licensing boundaries.

At this publication checkpoint, ov.radiomics is the candidate adapter in upstream PR #1096, awaiting maintainer merge and a release. The public-registry extra remains an inactive commented placeholder. To evaluate it, install an accepted local wheel and use an importable OmicVerse checkout containing that PR; a released OmicVerse registry-install command is not yet promised.

The shared Rust core without Python

 
        flowchart TD
    R[ov.radiology: geometry and review] -->|explicit image and mask inputs| P[Independent ov_radiomics package]
    A[ov.radiomics: optional lazy adapter] -->|optional package installation| P
    P --> C[Shared Rust core]
    L[Independent radiomics CLI] --> C

The diagram assigns responsibilities; it does not make DICOM conversion a new radiomics feature or transform CT voxels into an AnnData expression matrix. Existing arrays and external embeddings enter only through their documented, identified contracts. Optional interoperation does not add an OmicVerse runtime dependency to the independent package.

The adapter becomes an installation promise only when a compatible independent wheel and the corresponding OmicVerse extra are actually released. Importing OmicVerse must not eagerly import that optional package or new imaging backends.

The independent package is MIT licensed; OmicVerse is GPL-3.0. The GPL project may depend on MIT code. GPL implementations must not be copied back and redistributed as MIT code. See the contribution policy.

Read the native boundaries for optional Python paths, unsupported adapters and explicitly deferred capabilities. Read the English installation guide for candidate wheels and the separate CLI.
